(steps: `index`, `search`, `storage`, `effort`, `pager`, `overlap`; `--projects <folder>` reads another folder).

## Fix 1, index build in parallel (round 10 item 2)

The default `TranscriptIndex.Build` reads the files on several threads, each into a ledger of its own, then combines the ledgers in
the order the one-after-another build reads them. The one-after-another build stays as the reference (the overload with a reader).

The data moved during the day (live sessions), so the before and after numbers below were taken on the same snapshot: 862.5 MB,
27,955 messages counted once. Fresh process each time, `--repeat 1`, five runs each:

| Index build | Runs (s) | Median | Peak working set |
|---|---|---|---|
| Before (item 1 build) | 4.03, 3.66, 4.00, 3.88, 3.78 | 3.88 s | 86 to 100 MB |
| After (parallel) | 1.61, 1.54, 1.69, 1.56, 1.57 | 1.57 s | 167 to 207 MB |

Output: the test `TranscriptIndexParallelTests` compares every field of the index (sessions, totals, models in order, skipped files)
between the two builds on a fixture with copied messages, a message written twice, one message under two models, unkeyed records, a
subagent file, files created out of name order and a locked file. A mutation that drops the per-file usage rule fails the test.

Where the time goes (probe on the same folder, not committed): reading the raw bytes in parallel takes 0.03 s, decoding the lines
0.3 s, and the JSON summary of every line 0.7 to 0.9 s. The merge takes about 0.02 s. What is left is the JSON parse itself.

## Fix 2, search pre-filter for a word with an escaped character (round 10 item 2)

A word with a backslash or a quote was never pre-filtered, so every line of every transcript was parsed. Now it is looked for by its
longest run of plain characters (`RawProbe`: "C:\Windows\System32" gives "System32"). A message that holds the word also holds that
run unescaped in its raw line, so no match is lost. The test `HistorySearchRawProbeTests` checks the probe values, the path search,
and a reference that parses every line (the rule before this fix) on twelve queries over six sessions with escapes, quotes, tabs,
a newline and an emoji.

the bench makes first, so its process peak is the index's:
