## Open / not decided
- Match semantics for find: substring, case-insensitive (same as history search). Assumed: the whole trimmed query is one substring (not word by word as the history search matches); a line is a hit once.
- Hits inside the cut part of a tool result count as hits (the line is the unit). Searched text: the message text, each tool result whole, and each tool call's name, file path and full command.
- Find's cap is 2,000 lines; the cache keeps the results of several queries for the file key of the shown transcript (a changed file drops them).
- Jump keys (assumed; the plan named `Alt+[`/`Alt+]` for file writes and "compaction" with no key): `[`/`]` prompts, `{`/`}` failed tool results (the line shown in red), `Alt+[`/`Alt+]` file writes, `Ctrl+[`/`Ctrl+]` compactions. A jump starts from the focused line, else the first line on screen. The marks come from the same pass as the turn facts, so a jump does nothing until that pass ends (a moment after the page shows).
- The find box's query is pre-filled from a search result, so a multi-word search may find fewer lines than the search (the find matches the words as one phrase).
- Search results name a folder with the labels of all history folders (the same labels as the Usage page), not only the result's own working folder. The rail's folder headers are unchanged: two rail groups with one leaf name still show the same name (only Search and Usage disambiguate).
- Transcript lines are text blocks, so the keyboard focus ring is the selection colour behind the line, not an edge (the search rows and the effort items have an accent edge).
- Full result: capped at 200,000 characters; a surrogate pair at the cap is not split. Copy command copies the first Bash call of the record.
- Test-only flags added: `--search <text>` (starts the rail's search) besides `--find <text>`, so the search results can be screenshotted.
- Status-bar buttons and pill tabs already carry their text as content (the automation name comes from it), so no names were added there.
- Timing of a jump and of a find is logged as `find:` and `jump:` lines in the scratch state's app log (line numbers and counts only, no text).
