## Decisions made while building

- Item 1: the key is a fresh stat (`FileInfo.Refresh`) taken before the read, in `ReadOne`, and compared again in `FromCache`. A stat
  that fails is not a cache hit, and the read reports the error as it does for any file. The window is 2 minutes, measured against the
  fresh write time and the start of the build. Tests use file times, not an injected clock: `Core` has no `InternalsVisibleTo` and the
  fixture files are written an hour old, so the cache tests keep their meaning. Not covered: a writer that keeps its handle open can
  leave the directory entry's length and write time behind for longer than 2 minutes, and the rule cannot see that. Taking the length
  from an open handle was not adopted: it opens every transcript on each start, with a sharing mode the writer may refuse.
- Item 2, reproduced on the code before the item: `Load` threw NullReferenceException for `"files": null` and for `"path": null` (two
  tests fail on the old filter, and pass on the new code); `Save` let an ArgumentException out (a path with a null character), which
  the IO filter did not catch. Logging: `Build(root, cache, log)` takes an optional `Action<string>`, the `EventLog` pattern, and the
  App passes `AppLog.Write`, so the lines land in `logs\app.log`. A missing cache file is not logged; a damaged one is.
- Item 2, NOT reproduced: the review's lone-surrogate example for `Save`. The reader refuses a lone surrogate escape (a high one
  `\ud800` and a low one `\udc00` both throw InvalidOperationException in `JsonDocument.GetString`), so no string of that kind reaches
  `Save`. Test fixtures with either failed in the reader, not in the save, and were dropped. The save tests use a read-only cache file
  (the move fails, the old cache stays), a cache folder in the way, and the null-character path.
- Item 2, found and NOT changed (outside the plan, pre-existing, for the owner): one transcript with a lone surrogate escape makes the
  reader throw, and `Combine` rethrows every non-IO error (the designed rule, judged correct in the review), so the whole history load
  fails for that one file. The same happens with the one-after-another reader. Options for the owner: skip a transcript that throws a
  parse error as an unreadable one, or keep failing loudly.
