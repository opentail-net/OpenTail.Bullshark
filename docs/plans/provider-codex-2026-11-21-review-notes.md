1. Should fix (before C) - App SessionWindow.xaml.cs KeyOf (line ~42) and every KeyOf(tab.Key) call (Tabs.cs, Split.cs, Rail.cs, PopOut.cs):
   KeyOf builds the key from the window's active provider, not from the tab's own provider. OpenTab.Provider (A4) exists so "an open tab stays with its own provider",
   but nothing reads it. Identical for Claude today; once C adds a provider switch, a Claude tab looked up after a switch to Codex gets `codex:<id>` and misses its terminal,
   hidden-set and right-pane entries. Suggest: add KeyOf(OpenTab tab) => new(tab.Provider, tab.Key) and use it wherever a tab is at hand; keep KeyOf(string) only where no tab exists.
2. Should fix - Core/Library/SessionLibrary.cs Read, migration branch (lines ~205-210): the read-only path Load/LoadAll now writes (backup + Write). If the folder is read-only or the disk is full,
   File.Copy/WriteAtomic throw IOException/UnauthorizedAccessException from a "read". The App catches StoreErrors.IsExpected in SessionWindow.Library.cs:50 so the rail shows without marks (acceptable),
   but then the migration is retried (and a backup attempted) on every load. Failure is safe (see 3e). Suggest: a test that a read-only library does not lose entries, and optionally log once.
3. Note - SessionKey.Parse/HasProviderPrefix (SessionKey.cs): a bare id that contains a colon and starts with lower-case letters/digits/hyphens before it (for example `abc:def`) is taken for provider `abc`.
   Claude ids are UUIDs (no colon), so no real input today; empty string parses as bare Claude id "" (same as before); `claude:` gives an empty id key (harmless). UUIDs are never mistaken (hex plus hyphens, no colon).
4. Note - SessionLibrary.Read: if a file holds both `X` and `claude:X`, the later pair in file order silently wins after migration. Only reachable by hand edit; the backup holds both.
5. Note - ClaudeProvider.ReadPageAsync: wildcards and separators refused; `..` as id only searches for `...jsonl`, harmless. FindTranscript sweeps all subfolders (existing behaviour). Line bounds clamp to 0. No finding.

## Stage C review (Sonnet)

Range bc88961~1..88924a6. Code read; no process started; no real Codex or Claude file opened. Not run: build, tests, the window.

Findings, most severe first:
1. **Should fix** (borderline Must; breaks C-D6 "no trust step") SessionWindow.xaml.cs:434 and 743-766. The Claude pass keeps running under Codex. When a due run needs an untrusted folder, `ShowTrustStep` starts a `claude` terminal and, for a new step, forces `select = true` (line 759), so `ShowOnly(step.Terminal)` replaces the Codex tab on screen. 2. **Should fix** Tabs.cs:474 (and 210). With the last tab closed under Codex, `OpenSetupTab(null)` shows the Claude setup page. Already open point 2; `AddTab` also gives that setup tab `Provider = Codex` (harmless: every key use is Kind-guarded). Also NewTab_Click:101 is fine.
3. **Should fix** CodexSetupCheck.cs vs the terminal start (assumption, not verified: the terminal library starts `StartupCommandLine` with CreateProcess, no shell). The check reports OK for `codex.cmd` or `codex.ps1`, but `codex -C ...` as a bare command line finds only `codex.exe`. An npm install (shim .cmd) would pass the check and fail to start in the tab. Verify with the owner at the screen; if confirmed, accept only `.exe`, or start via `cmd /c`/`pwsh` (then quoting needs a re-check, see area 2).
4. **Should fix** CodexHistorySource.cs:127. The index name is not collapsed or cut (only trimmed): a `thread_name` with a newline or 10 000 characters goes into the rail label unchanged. Only the first-user-text title is collapsed and cut. Apply `Cut(Collapse(name))` to both.
5. **Should fix** CodexHistorySource.cs:141. `text[..80]` can split a surrogate pair (emoji at position 79/80), leaving a lone surrogate in the label. Back off one char when `char.IsHighSurrogate(text[79])`.
6. **Should fix** RolloutReader.Open / Summarise:96. `ReadLine` has no length cap: a rollout line of hundreds of MB (or a zstd bomb) is read whole into memory; an OutOfMemoryException is caught per file, but the rail read stalls and the process balloons first. Cancellation is checked per line only (the App passes `CancellationToken.None`, so it is never cancelled). Cheap guard: read with a bounded buffer and skip a line over a cap (say 8 MB), count it in SkippedLines.
7. **Should fix** CodexHistorySource.cs:112. A truncated zstd file that throws mid-stream loses the whole file (skipped, counted) even if the session record was already read; one that ends silently gives a partial summary with partial counts (message counts then look real). Acceptable for C; note in the plan. No test covers a truncated .zst, a malformed line in the middle of a file, or an unknown record type (the code handles all three: bad line counted, unknown type ignored by the switch, exception caught).
8. **Note** ResumeCodex (Codex.cs): a Codex tab whose process has exited stays open, and "resume" of that id only activates the dead tab; the owner must close it first. A "New Codex session" tab and a resume of the same thread can run two processes on one conversation (B6, known).
9. **Note** ResumeCodex: a missing session folder falls back silently to `_options.WorkDir`; status text does not say so.
10. **Note** Claude: a library file that cannot be migrated used to throw out of Load and now returns entries in memory with one log line per process (intended C-D8). It is a behaviour change for a read-only Claude library; the only one found.
