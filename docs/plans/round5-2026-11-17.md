## Contracts this must satisfy

| Member | Promise |
|---|---|
| `SupervisorPolicy` | Never starts or resumes a session the owner stopped, or one that failed; alerts once per entry; at a run's limit nothing new starts. |
| `SupervisorRunner` | A failed start/resume is recorded and alerted; a successful one is never recorded as failed; the pass goes on for other sessions. |
| `AttentionList.From` / `Gained` | What needs the owner now; `Gained` = new arrivals, which trigger sound and flash once. |
| `EventLog` | Append-only JSON lines under the file lock; readers skip a cut-off last line. |
| `TranscriptArchive` | Never moves a listed or recorded session; never overwrites; never deletes. |
| `StoreErrors.IsExpected` | The one list of failures a user action reports in the status line. |

## Decisions made while building

- D1 (item 1): the stop guard reads `LastState` and `LastAlert`. The runner keeps `stopped`/`failed` as `LastState` while the listing
  does not show the session. Before, `not listed` erased it, and a limit alert then replaced `LastAlert`, so a removed stopped session
  could be resumed. Side effect: the `stopped -> not listed` state event is no longer written; the Stopped alert still is.
- D2 (item 2): `Emit` is called after the start/resume `try`, so only a failure of `Carry` makes a failed start. `Write` catches every
  `StoreErrors.IsExpected` failure (the timeout included) and logs it as `events: not written`. A start whose event write timed out
  keeps its record and is not alerted.
- D3 (item 3): the duration counts from the start time once it has come (`RunSpend.ElapsedOf`), from the creation otherwise, and is
  zero before the start. "Start now" moves the start time to now instead of clearing it (`RunStore.StartingNow` has a three-argument
  form; the two-argument form uses the clock). The existing `StartingNow` test now asserts the moved time.
- D4 (item 4): `TranscriptArchive.Archive` takes a null protected set as "no listing yet" and refuses every file, and refuses a file
  written within `RecentWindow` (24 h) by its last write time. The storage tests' default fixture time moved to 2026-11-01 so that old
  fixtures still archive. In the window, `_listingKnown` is set by a pass that listed the sessions and cleared by a failed pass; the
  Archive button is off, with a note, while it is clear or the state file cannot be read. Archive also refuses when the state file
  cannot be read, since its records are part of the protection.
- D5 (item 5): `EventLog.Write` ends a cut-off last line with a newline before it appends, under the same lock. The cut-off line is
  still skipped on read, and only that line.
- D6 (item 6): `Gained` counts only waits as "already waiting". A notice (overlap, conflict) that a session had does not make its
  first wait old news. A wait is still compared by session name, so a change of reason between two waits is not new, as before. Two
  existing tests asserted the old rule (`ConflictAttentionTests`, `OverlapAttentionTests`) and now assert the block is announced.
- D7 (item 7): "live" is read per session, not per run: a session is live when the active listing shows it and its state is not
  `done`, `stopped` or `failed` (`FileOverlap.LiveRecords`). Clashes are found among live sessions only, so a finished run's shared
  file leaves Needs you, and a run whose sessions are all finished has no notices. Run records and the budgets still count every
  session. A conflict's key is the session and its sorted file set (`AttentionItem.Files`); the window keeps the keys it has shown
  (`_announcedConflicts`, for the life of the window), so re-entering done with the same files is silent. Overlap notices are not
  remembered this way: an overlap that clears and comes back is announced again. The merge result is still dropped when a coder leaves
  done (the memory of shown conflicts makes that silent); I did not keep it until HEAD changes, which would need a git call per pass.
- D8 (item 8): the level the owner was told is stored on each session record (`SessionRecord.LimitLevel`: `near`, `reached`, or
  null), so an alert that replaces `LastAlert` no longer repeats the notice. A notice is raised when the level rises. A level that
  falls (the owner raised the limit) is recorded with `SupervisorAction.LimitLevelSet`, with no notice and not counted as an action.
  One notice per run: the lead session, which is the first session of the run with a session id, carries the notice and the
  `LimitReached` item; every session is still held to the budget (`RunBudget.ForSessions`, `Notify`). `LimitReached` shows under
  Needs you on the lead's row when no other reason applies (this revises D4.4); `LimitNear` stays out of Needs you. A run that was
  already near or reached before this change may get its notice once more, because the old records have no level.
- D9 (item 9): the cache keeps, per transcript, the byte offset of the complete lines read so far, the usage ledger and the writes.
  A file that grew is read from that offset only, and the usage of the whole file comes from the shared ledger, so a message split
  across two reads counts once. `TranscriptReader.Summarize` gained `firstLine` (optional, default 0) so the line-keyed usage of
  unkeyed records keeps its numbers. A line counts when its newline is written: the last record of a file is taken one line later,
  when its newline comes. A file that shrank, or was rewritten at the same size, is read from the start. A run with one session and no
  limit reads no transcript at all (`FileOverlap.NeedsTranscripts`). `SessionWritesCache` takes an optional opener, the test seam.
- D10 (item 10): the timeline draws the newest 2,000 rows of the chosen run and session, with "Show older" adding 2,000 more (the
  plan's second option; virtualizing rows that were already created as objects would still create them all). The outer ScrollViewer
  is gone, so the ListBox scrolls and virtualizes its own rows. The log was already read on a pool thread, and that is unchanged. A
  row shows `yyyy-MM-dd HH:mm:ss`. `SessionSpec.RunId` (set by `RunPlan.Build`) and `SupervisorEvent.RunId` (set by the runner) name
  the run; an event without one, from an older log, matches by session name as before. A reused name therefore shows another run's
  events only in those old lines.
- D11 (item 11): the Changes read of the written files moved to Core (`TranscriptWrites.Of`), which catches every `StoreErrors`
  failure and returns it as the note; the window's read is guarded too, so a failure shows a message and Refresh comes back. Storage's
  two loads are guarded and show their failure in the status line of the page. The window remembers the chosen project, and reads its
  transcripts again after an archive or a restore. Storage already read off the UI thread, and that is unchanged. The window wiring has
  no unit test: the repository's tests cover Core only, so the rule is tested in `TranscriptWritesTests` and the rest is built and run.
- D12 (item 12): the launch length counts each argument as the command line writes it. `ClaudeCli.EscapeArgument` follows the rules of
  `ProcessStartInfo.ArgumentList` (wrapping on whitespace or a quote; doubling backslashes before a quote and at the end of a wrapped
  argument; an empty argument as two quotes). `CommandLineLength` and the refusal in `RequireCarriable` use it, and so does
  `SetupPlan.LongestCommandLine`, which `ResumeText.Fit` takes its measure from. `Fit` cuts again while the text is still over, since a
  cut character can take more than one off the line, and it stops early when the text is over even without its tail. The escaping is
  checked against Windows' own `CommandLineToArgvW` on the round-trip test. Whether whitespace in `char.IsWhiteSpace` terms is the wrap
  rule of `ArgumentList` is from memory of the runtime's source; the test fixes the behaviour that matters (the program reads back what
  was written).
- D13 (item 13): `StartTime.Parse` builds the next time as a wall-clock time in the zone, with the offset of that day (`Occurrence`),
  and does not move an instant by a day. The zone is a parameter (the old signature uses `TimeZoneInfo.Local`). Tests use Berlin
  (`W. Europe Standard Time`, or `Europe/Berlin` off Windows) across the March and October 2026 changes. The waiting row says the day
  when the run is not due today (`StartTime.Describe`: `HH:mm`, or `yyyy-MM-dd HH:mm`).
