## Decisions

B1 (copy review prompt):

- **Files:** all changed files of the Changes list (the `git status` list), not per-file checkboxes. Files written by the session are not added.
- **Length:** the 30-file cap applies first; then trailing files are dropped while the prompt is over 1500 characters, and "and N more" counts them. File names are never cut.
- **Note:** trimmed, cut to 500 characters, sent as typed. Kept while the same session's Changes tab is refreshed; cleared when the tab shows another session, so one session's note never goes into another's prompt.
- **No files:** the button is off (not "copy an empty prompt"). The prompt builder returns null for no files.
- **Status line:** "Review prompt copied (N files)" counts all changed files, even when the prompt names fewer.
- **Clipboard:** only `ExternalException` (busy clipboard) is caught, as the resolve prompt does.
- **Session name:** the rail record's name; "this session" when there is no record.
- **Paste guard (outside B1's files, one hunk):** the window's paste handler (`OnPanePreviewKeyDown`) pasted the clipboard into a terminal whenever `PasteTarget` found one, and `PasteTarget` can be a session of the right pane that is still on screen while the Changes tab is shown. Ctrl+V in the note box would therefore have sent the clipboard into that session. The handler now leaves a paste alone when WPF's focused element is a `TextBoxBase`. A terminal with focus has no WPF focused element, so terminal paste is unchanged. The rail's search box gets the same fix, since it had the same leak (found while building B1, not seen in a running window).
