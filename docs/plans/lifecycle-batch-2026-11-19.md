## Contracts (read in the code 2026-11-19)
- `SupervisorPolicy.Decide(spec, record, agents, now, rules, reached)` (Core/Supervisor/SupervisorPolicy.cs) is pure and returns `SupervisorAction`s (`Start`, `Adopt`, `Resume`, `Alert(Role, AlertKind, Detail)`, `LimitLevelSet`). `DecideSession` handles: adoption of a listed row with the spec's name when the record has no id; first start; a record with no id (failed start: nothing until the owner retries);
  a record whose id is not listed -> `DecideLost`; stale/blocked/stopped/failed rows -> alerts once per entry into the state; working/done/busy -> `[]`. `DecideLost` returns `[]` for a stopped/failed record, the stale-blocked hold, the run's limit; otherwise counts `record.RestartTimes` in the last hour against `SupervisorRules.MaxRestartsPerHour` (3): at the cap an alert once (restart-loop), else `Resume`.
- Alerts become `LastAlert` text `"{AlertKind}: {detail}"` on the record; `AttentionList` reads the prefixes (`RestartLoopPrefix`, `StoppedAlertPrefix`, `FailedAlertPrefix`, `ResumeFailedPrefix`, `StaleBlockedAlertPrefix`) into `AttentionReason`s; `ToastText.ReasonText` and `ToastCategories.Of` map reasons to words and toast categories. A new alert kind needs all of those four places, following the `RestartLoop` pattern, and a test in each.
- `AgentInfo` (Core/Claude): `SessionId`, `Name`, `EffectiveState` (stale rows come from `DaemonStatus.IdleListing`), `StartedAt`. A listed row's `done` state cannot be told from idle; `stopped`/`failed` rows are never alive.
- The supervisor never types into a session, never accepts/merges. Nothing in this batch starts a real `claude` (tests use `FakeCliRunner` / pure calls only).
- `SessionRecord.RestartTimes` is appended on every resume (`SupervisorRunner` ~288 and ~343); keep that. Settings in ui.json: read through `UiFile.Read`, written through `UiFile.Set`/`Update`; `EscalationChoices` is the pattern for an "Off / N min / Custom" choice row; Settings > Naming holds the re-alert interval.
- Cache facts per live session: `_runningFacts[sessionId].LastRequest` (App; `TailFacts`), refreshed each pass; no new transcript read may be added.

## Steps (Core first with tests, then App)
- [ ] L1. **Name-clash guard.** In `DecideLost` (before `Resume`): if another listed row, with a **different** session id, has the spec's name and is alive (state working, blocked or busy; **not** done, stopped, failed or stale), do not resume: `Alert(NameTaken, "name '<name>' is taken by session <short id>; resume would make a second one")` once per entry (not repeated while the alert stands). New `AlertKind.NameTaken` + prefix constant + `AttentionReason.NameTaken` + words + toast category Problems, following `RestartLoop` in all four places. Tests: clash with a working row -> alert; with a done row -> resume as before; the same id listed under the name (that is not "lost") untouched; alert not repeated; cleared when the clash goes (the resume then runs).
- [ ] L2. **Restart backoff.** In `DecideLost`: after the first restart in the last hour, wait before the next one: gap = 1 min after the 1st, 2 min after the 2nd (so at most 3 per hour still holds); a pass inside the gap returns `[]` (no alert; the loss shows in the rail as today). Constant table in `SupervisorRules` (`RestartGaps`), default `[1, 2]` minutes; tests with an injected clock for each step, for an old restart outside the hour, and that the cap behaviour (alert once) is unchanged. Update `SupervisorRules` tests.
- [ ] L3. **Silent-working notice.** Core `Supervisor/SilenceCheck.cs`: `SilenceCheck.Find(IEnumerable<(string Name, string SessionId, string State, DateTimeOffset? LastRequest)> live, DateTimeOffset now, TimeSpan threshold)` -> names of sessions listed `working` whose last request is older than the threshold (null last request = not flagged: unknown). A notice, not an alert: no state change, nothing sent. `AttentionReason.Silent` ("no output for N min; may be a long command") added to `AttentionList` as a notice that appears while the condition holds and goes away when the session writes again; toast category Notices; **not** announced by sound/flash on its own more than once per spell (use the existing notice-key mechanism: `NoticeKey`). Setting `silentMinutes` in ui.json (default 45; 0 = off; clamp 5 to 1440; junk -> default) with a pure reader and `SilenceChoices` for the Settings row (Off / 30 / 45 / 60 / 120 min / Custom (N), like `EscalationChoices`). App: fill the input from `_agents` + `_runningFacts` each pass; Settings > Naming gets a pill row "A working session with no output for". Tests: flagged / not flagged / unknown last request / not working / threshold edges / setting reader / choices.
- [ ] L4. **Scenario replay tests.** `tests/.../Supervisor/SupervisorScenarioTests.cs`: a small helper that runs a scripted sequence of passes through `SupervisorRunner.CheckOnceAsync` with `FakeCliRunner`, an in-memory/temp store and a fixed advancing clock, each step giving the listing (JSON as `claude agents --json` prints it, **synthetic** ids/names, no real data) and the expected actions/records. Scenarios: first start; adopt a listed name after a lost record; a session vanishes -> resume -> vanishes -> backoff gap -> resume -> cap -> one restart-loop alert -> hour passes -> resume again; stale blocked once; stopped never resumed; name clash alert then resume after the clash row goes; a `done` row left alone. At least 8 scenarios. If a scenario exposes a bug in the code, do not fix it silently: add the failing case as `Skip`-free expected behaviour only if the policy is clearly wrong, else record it in the plan.
- [ ] L5. Docs: README bullets (name clash alert, backoff, silent notice with its setting); `live-run-checklist.md` items (L3 with a real long command; L1 cannot be seen without two sessions of one name: note how to try with the fake claude); tick this plan.
