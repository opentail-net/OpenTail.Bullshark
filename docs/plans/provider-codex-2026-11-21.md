# Provider seam and a Codex rail (plan, 2026-11-21)

Status: **plan, nothing built.** It turns `provider-seam-design-2026-11-19.md` (tiers 0-4) into steps and adds what the Codex research found. Research report: scratchpad `codex-research.md` (Haiku researcher, 2026-11-21; each item marked VERIFIED/ASSUMED there; the orchestrator has re-checked only the items marked "checked" below).

## Goal
A dropdown at the top of the rail: **Claude | Codex**. Choosing one swaps what the rail lists (live rows, history, search, tags). Tabs already open keep their own provider and are untouched. Claude behaviour and its 2000+ tests do not change. Principle 3 holds: the window never types into a session or accepts anything for the owner.

## Review amendments (ChatGPT review of both plans, 2026-11-21; each point checked by the orchestrator)
Accepted and written into the plan below; the plan is **not ready for a coder until stage B has reported**. New order: A1 (the map) -> **B (spike)** -> amend this plan from B -> A2-A6 -> C.
- **R-1 Live rows by cwd+time are unsafe** (two terminals in one folder). Valid. Stage C does **not** claim Codex live rows. C shows Codex history (reliable thread ids), plus Codex terminal tabs the window owns. A tab is tied to a thread id only if B finds a reliable way to capture the id at creation (a SessionStart hook, `codex exec --json`, or app-server). Otherwise there is no live status for Codex.
- **R-2 `SessionDigest` is not provider-neutral** (it has `LimitStop`, `ContinuesSessionId`, `LastRecap`, `Compactions`, `AiTitle`), and **0 is not unknown**. Valid (checked: `TranscriptIndex.cs`). A2 defines a neutral `SessionSummary` (fields with the same meaning in every provider; counts nullable, null = unknown) plus a provider-specific extension. Claude's digest maps onto it without loss; the existing UI keeps reading the digest for Claude until each screen is moved. No Codex concept is forced into a Claude-shaped field.
- **R-3 Typed identity.** Valid. A2 adds `SessionKey(ProviderId, SessionId)`, used by the rail, the tab and terminal dictionaries, the library, tags/notes/archive, caches and persisted state; the persisted string is `claude:<id>` / `codex:<id>`. A1's map lists every dictionary or file keyed by a bare session id.
- **R-4 Migration vs downgrade conflict.** Valid. **Decided by the owner (2026-11-21): no downgrade support.** The new build migrates `library.json` in place (bare ids become `claude:<id>`); an older build is not expected to read it. One safety kept (orchestrator's addition, cheap): before the first migration the old file is copied once to `library.json.bak-yyyyMMdd-HHmmss` (never overwritten, never deleted by the app; name changed on 2026-11-21 to the one the code writes, with `-2`, `-3` when a name is taken). A5's test: an old-format file keeps its tags, notes and archive marks after migration, the copy exists and equals the old bytes, and a second run changes nothing.
- **R-5 App-server vs raw files.** Valid. Stage B compares the two (B5). Whether an app-server instance can see threads opened by separate interactive CLI processes is **unknown**; do not assume it. Approval boundary: a test asserts the watcher never sends an approval or a denial.
- **R-6 Zstd.** Checked locally 2026-11-21: `ZstandardStream` is in the **net11.0** reference assemblies and **not** in net10.0 (grep of both `System.IO.Compression.dll` references). So net11 has a BCL route; net10 needs a package, or Codex history is net11-only. B1 decides; the dependency stays out of Core if possible (a separate `OpenTail.Bullshark.Providers.Codex` assembly).
- **R-7 Compressed paging.** Valid: a zstd stream is not random access. B1b must show tail read, paging, find and cross-file search on a large rollout, memory use, and **no plaintext copy or temp file on disk** (privacy rules).
- **R-8 Capabilities.** Valid: avoid a growing list of booleans. A provider implements only the interfaces it has, and the UI asks whether the provider offers one. "Open a terminal" and "start a supervised session" are different interfaces.
- **R-9 Documents.** `provider-seam-design-2026-11-19.md` is marked partly superseded (its header). Ollama naming (tier 4) is deferred, unscheduled.

## Decisions taken (owner, 2026-11-21) and assumptions
- Dropdown swaps the rail only; no mixed lists. (Owner.)
- Later providers must fit the same seam. (Owner.) Design the interface against **three** providers on paper (Claude, Codex, one of opencode/Copilot/aider) so it is not shaped by two.
- A1 (assumption, **corrected 2026-11-21 from evidence**): the old wording "Codex has no `--bg` equivalent" was wrong. Codex has its own background mechanisms (a shared app-server daemon, seen in probe P03; `codex queue`, in its help text), and the owner's machine has the Codex desktop app. This app still does not use them. Its Codex rows are history from disk, and its live rows are **terminal tabs the window owns**. Stage C ends there; supervision is stage E and optional. See `docs/research/codex-evidence/README.md` for what has been checked.
- A2 (assumption): the supervisor loop, `claude stop/respawn`, trust, daemon health and limit-wake stay Claude-only and are hidden for Codex by capability flags.
- A3 (decision for the owner, section "Open decisions"): adding packages to Core (zstd, SQLite).

## Facts that shape the plan
Checked by the orchestrator in code (2026-11-21):
- `Core` has **no NuGet packages**; `App` has WPF-UI.Terminal and CommunityToolkit.Notifications. Targets: net10.0 and net11.0 (SDK 11.0.100 installed).
- 48 Core files and 22 `ClaudeCli` users reference Claude. Paths go through `ClaudePaths` (6 call sites: `ProjectsRoot`, `ConfigDir`, `ClaudeJson`, `ArchiveRoot`), which is a small, good seam.
- Live rows = `SessionRecord` from the supervisor (`claude --bg`), terminal = `claude attach` (`SessionWindow.xaml.cs:617-632`, `DetachedSessionWindow.cs:29`). History rows = `TranscriptIndex.Build(projectsRoot)` -> `SessionDigest` (`SessionWindow.Rail.cs:662`).
- `SessionLibrary` keys are bare session ids (tags, notes, archive); the design notes said `provider:sessionId`.

Researcher-reported, **to be re-checked in stage B** (a spike, before any plan item depends on them):
- Codex rollouts are `~/.codex/sessions/YYYY/MM/DD/rollout-*-<uuid>.jsonl.zst`: **62 of 63 files here are zstd-compressed**, 1 plain. Lines: `{timestamp,type,payload,ordinal}`; types `session_meta`, `turn_context`, `event_msg`, `response_item`, `world_state`.
- `~/.codex/state_5.sqlite` table `threads` (id, rollout_path, cwd, title, name, model, reasoning_effort, tokens_used, archived, created/updated_at, first_user_message, preview...) is a ready session list. `session_index.jsonl` holds names. `thread_history_1.sqlite` has turns with status (completed, failed, inProgress, interrupted).
- Token usage and **rate limits** are in rollout `event_msg` (`token_count`: `rate_limits.primary{used_percent, window_minutes, resets_at}`), so Limits is possible later.
- `codex app-server` (JSON-RPC, stdio/unix/ws) has `thread/list`, `thread/read`, `thread/status/changed` with `waitingOnApproval` / `waitingOnUserInput`, and `account/rateLimits/read`. That is the only source of a **Needs-you** signal; approvals are not in the files. Approval requests go only to clients that set `requiredHumanApproval`: a watcher must not answer them (principle 3).
- No JSON session list on the CLI; no `--name`; effort via `-c model_reasoning_effort=`; `-C <dir>`, `-m`, `codex resume <id|name>`, `codex fork`.
- Schema format is not promised by OpenAI (format drift risk, R2).

## Stage B results (2026-11-21, orchestrator; spike, read-only; no Codex session started; scratch probes outside the repo)

Probes: a net11.0 console app in the session scratchpad (structure only: line counts, record types, payload key names; no values printed); `codex app-server` started by the probe over stdio and stopped by it; `codex app-server generate-json-schema` (no state touched). Codex CLI 0.171.0. Four `codex` processes were already running on the machine and were not touched.

- **B1 (decode, done):** `System.IO.Compression.ZstandardStream` decodes rollouts on **net11.0** with no package. The largest rollout (32.8 MB compressed, 70.6 MB text, 15,877 lines) was decoded and every line parsed in 290 ms (252 MB allocated, process peak working set 156 MB). A 468 KB rollout took 24 ms. One plain `.jsonl` rollout (27.9 MB) also parses. On **net10.0** the same code fails: `CS0246: ZstandardStream could not be found` (confirms R-6). Of 63 rollouts, 62 start with the zstd magic bytes and 1 is plain JSON (checked by magic bytes only).
- **B1b (paging, partly done):** zstd has no random access. Any page or tail read decodes from the start of the file: about 0.3 s for the largest rollout (measured for a full decode with JSON parsing). Design consequence: a per-file line-offset index, kept in memory or in a cache holding offsets only (no text on disk), is needed for paging. Cross-file find was not timed beyond this decode.
- **B2 (SQLite, done for files; .NET route not tested):** `state_5.sqlite` and `thread_history_1.sqlite` are WAL-mode. Opening them read-only (`mode=ro`) worked while Codex was running. Observed: `mode=ro` still updates the `-shm` index file (its timestamp changed); the main database file's timestamp did not. No BCL SQLite exists, so a .NET reader needs a package (`Microsoft.Data.Sqlite`, MIT, to confirm). Relevant tables (names only): `threads` (63 rows: id, rollout_path, cwd, title, name, model, reasoning_effort, tokens_used, archived, created_at, updated_at, first_user_message, preview, is_pinned, project_id, and more); `thread_turns` (1,996 rows) and `thread_items` (24,614 rows, with item status). A no-SQLite route also exists: `session_index.jsonl` (53 lines, keys id, thread_name, updated_at only).
- **B3 (field map, done as structure; fixtures not yet written):** record types in rollouts: `session_meta`, `turn_context`, `event_msg`, `response_item`, `compacted`; the plain file also has `token_usage_record` and `world_state`, so the set varies by version (R2 evidence). Map to `SessionDigest`: SessionId <- `session_meta.id` / `threads.id`; FilePath <- `threads.rollout_path`; ProjectFolder <- `session_meta.cwd` / `threads.cwd`; First/LastActivity <- `threads.created_at`/`updated_at`; turns <- `turn_context` records; user and assistant counts <- `response_item.role`; ToolCalls and Names <- `response_item.name`; LastAssistantText <- `event_msg.last_agent_message`; LastModel <- `turn_context.model` / `threads.model`; ContextTokens <- `event_msg.model_context_window`; Usage <- `event_msg.info` / `token_usage_record.usage`; FirstUserText <- `threads.first_user_message`; titles <- `threads.title` / `name` / `session_index.thread_name`; Compactions <- `compacted` records. **Null for Codex** (no field found): Recap, ContinuesSessionId, FilesWritten, failed-tool-call count, and the limit stop. Each of these is a capability decision for A2.
- **B5 (compare the two read paths, done with limits):** (a) files: readable while Codex runs, with the format-drift risk above. (b) `codex app-server` over stdio: `initialize` ok; `thread/loaded/list` returned 0 (this server had loaded no threads); `thread/list` returned 59 threads (the `threads` table has 63 rows; the 4-row difference was not checked), **every one with status `notLoaded`**. So a separate server sees the threads but not their live state. Live states (`thread/status/changed`: `waitingOnApproval`, `waitingOnUserInput`) appear only for threads loaded by that same server. The schema marks `requiredHumanApproval` as an opt-in initialize capability; a client that does not declare it is not offered approval prompts (per the schema text). No approval was pending and none was answered; none was provoked. **Not tested:** what a client sees when an approval is pending.
- **B6 (session identity, not proven):** candidates, in order of reliability: (1) the app-server's `thread/start` returns the id to the client that starts the thread; (2) the TUI accepts `--remote <ws://|unix://>` (flag present in `codex --help`, not tested: it needs an interactive TUI); (3) a `threads` row created near launch with the same cwd: time-and-folder matching, unsafe with two terminals in one folder (R-1); (4) `codex exec --json`: not run, because `exec` starts a model turn. **Verdict:** no route is proven. Stage C must not claim a tab's thread until (1) or (2) is tested with the owner at the screen.

### B4 decisions (2026-11-21; the owner was away, so the orchestrator settled these; the owner may overrule any of them)
- **O1 (decided): Codex history only in net11.0 builds, with no package in Core.** Evidence: B1, `ZstandardStream` decodes rollouts on net11.0 with no package and does not exist on net10.0. Reason: Core has no packages today, and a zstd package on net10.0 is a supply-chain and licence review for an optional provider. Codex is compiled in under `#if NET11_0_OR_GREATER`; on net10.0 the dropdown offers Claude only. Revisit if the owner needs Codex on net10.0.
- **O2 (decided): no SQLite in stage A or C.** Evidence: B2, there is no BCL SQLite and the state files need a package. Stage C reads rollouts (`session_meta`, `turn_context`, `response_item`, `event_msg`) and `session_index.jsonl` (ids, names, update times).
