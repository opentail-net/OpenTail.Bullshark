## Order: measure first, then fix, then lock in with tests
Rule for every performance step: add a Stopwatch/count log line (no content), run it on the owner's real data (scratch state, `--no-pass`, real transcripts, read-only), record **before and after numbers** in the plan, and keep the change only if it helps or removes risk. A step that shows no problem is closed with its numbers and no code change.

## Contracts (to verify; from the report)
- `SessionWindow.Rail.cs` `RefreshRail` clears and rebuilds the whole tree on the UI thread (rows of collapsed folders too; a `ContextMenu` per row from `SessionWindow.Library.cs`) on every pass (15 s). Selection restore (`RestoreSelection`), expanded state (`_expanded`), the tag filter, search matches and group-by-tag all feed it; `ShownHistoryFolders()` is the single folder list (magic rename reads it).
- ui.json is read about four times per pass on the UI thread (`Rail.cs` ~378, 386; `Attention.cs` ~234, 250), each with a 2 s wait (`UiFile.UiWait`) when contended; `UiFile.Read/Set/Update` lock and re-read.
- `TranscriptView.cs` ~203 and ~404: `pager.ReadPage` (file I/O plus about 200 JSON parses) on the UI thread; "Load earlier" adds blocks without a cap into a non-virtualised StackPanel (the 60 MB transcript has 16,519 lines).
- `_terminals` keeps one terminal control per recorded session until closed (`SessionWindow.xaml.cs` ~565, `SessionWindow.Tabs.cs` ~344): memory over 12+ hours.
- `Core/Trust/ClaudeTrust.cs` ~76-80 parses all of `.claude.json` each pass and every 3 s during a Trust step (R3 limited the pass rate, not the parse).
- Existing behaviours that must not change: Needs-you never filtered; selection kept across a refresh; transcript pane kept when no live session (RestoreSelection guard for Search/Transcript/Changes/Insights/Settings); tab close selects a neighbour; quiet hours/notify gates in `AnnounceAttention`.
- No new package for tests beyond what the repo already uses (xUnit); a new test project is allowed.

- [ ] Q4. **Trust file parse cache.** Parse `.claude.json` only when its length or write time changed (cache the parsed `ClaudeTrust` per path); keep the one retry on a torn read and the "no file = trusts nothing" rule; measure the file's size and parse ms on the owner's machine first and say if it was worth it. - [ ] Q5. **Rail rebuild: measure, then skip when unchanged.** First log item count and ms per `RefreshRail` on real data. Do not rebuild rows of collapsed folders until they are expanded **only if** the measurement shows it matters (decide with numbers; skipping must not break select/restore/search "select row" or the magic rename's visible list). Tests for the signature as a pure Core helper (same inputs equal, each input changes it, clock bucket).
