## Contracts (read in the code 2026-11-19)
- `Core/Health/SetupCheck.Run(claudeDir, claudeJsonPath, pathVariable)` returns `SetupItem(Area, Name, State, Text)` rows for settings.json, `.claude.json` (MCP servers, hooks via `CheckProgram`) and CLAUDE.md; it **never checks that `claude` itself is on PATH** (**checked**: only the three Check* calls). `SetupState` has Ok/Warning/Problem (+ not checked). `SetupCheckDialog` shows each row as a coloured dot with no text (`SetupCheckDialog.cs` ~90-97). The Night preflight reads the setup problem count.
- `App.xaml.cs` ~31-34: `DispatcherUnhandledException` logs `unhandled: {exception}` to `AppLog` and sets `Handled = true`: no crash file, no status notice (**checked**). `AppLog.Write` goes to `<state>\logs\app.log` (rotates at 5 MB). The log can carry CLI output (`ClaudeCli.cs` ~191 says so; F8 cut CLI messages to one line, 200 characters).
- `ThemeStore.Load(stateFile)` (App/RailTheme.cs ~130-134): returns Light only when ui.json says `Light`, else Dark; it never reads the OS (**checked**). A saved choice must still win.
- `scripts/Start-OpenTail.Bullshark.bat` starts `bin\Debug\net10.0-windows\` (an old folder; the csproj targets `net10.0-windows10.0.19041.0`) and passes demo arguments (**checked**). The App csproj has no `<Version>` (**checked**).
- A failed pass shows the raw exception on the status line (`SessionWindow.xaml.cs` ~435-436) and as "Supervisor problem: ..." under Needs you (`PassHealth`, `SessionWindow.Attention.cs` ~78) with no install/PATH hint.
- `Core/Claude/VersionDrift.cs` knows the claude CLI version; `Heartbeat` (Core/Health) writes `heartbeat.json`; `AttentionList.From` is the attention source; `SearchView.cs` ~109-110 says "No session says every word of ..." for both "searched, no hit" and "nothing searched"; `StorageView.cs` ~140 and `TimelineView.cs` ~116 empty states give no next step; zoom "-", "+", "100%", the theme mark and the filter box are mouse-only (`SessionWindow.xaml` ~31-39, 82-89); chords appear only in tooltips and the transcript hint.
- Privacy: no transcript text, tokens or full user paths in any diagnostics output; `cache\` (index cache holds user text, README F13) is never included. Principle 3: nothing sent to a session; the app still makes **no network call** of its own.

## Steps (Core first with tests, then App)
- [x] B1. **`claude` on PATH check.** `SetupCheck` gets a first row "Claude Code: claude" using the same program lookup as `CheckProgram` (PATH/PATHEXT search): Ok with the version when found (version text from the existing `VersionDrift` source if it can be read without a new spawn per call; else just "found"), **Problem** with a next step ("install Claude Code, or add it to PATH, then press Check again") when missing. Tests with a fake PATH folder (create a unique temp folder, delete only it). The Night preflight and setup dialog pick it up unchanged.
- [x] B2. **Honest pass error.** A failed pass shows a short sentence with a next step instead of the raw exception: map the known causes in a Core helper `PassErrorText.Of(Exception)`: `claude` not found/`Win32Exception` -> "Claude Code could not be started: check that `claude` is installed and on PATH (Settings > Claude > Check setup)"; unreadable `.claude.json`/`runs.json` -> "<file name> cannot be read: <one-line reason>"; anything else -> the exception type and first line, 200 characters. Never a full stack or a path longer than the file name. Tests per mapping; the status line and the `PassHealth` row use it.
- [x] B3. **Crash file.** In `App.xaml.cs` `DispatcherUnhandledException` (and `AppDomain.UnhandledException` / `TaskScheduler.UnobservedTaskException` if not already handled): write `logs\crash-yyyyMMdd-HHmmss.txt` with the app version, OS, the exception type and message and stack **redacted by Core `Redactor`** (below), and the last 200 lines of `app.log` redacted; keep at most 10 crash files; set a one-line notice on the status line next time a window exists ("The app hit an error and kept going: logs\crash-....txt"); keep `Handled = true` as today. Core `Diagnostics/Redactor`: pure, shortens the user profile prefix to `~`, replaces any GUID-like session id with its first 8 characters, drops anything that looks like a bearer token or API key (`sk-`, `ghp_`, long base64/hex runs of 32+ chars), cuts each line at 400 characters. Tests including **planted canary strings** (a fake token, a fake path under the profile, a fake prompt line) that must not survive.
- [x] B4. **Diagnostics zip.** Settings > Claude gets "Save diagnostics…": writes `diagnostics-yyyyMMdd-HHmmss.zip` in a `diagnostics\` folder beside the state file and opens that folder. Contents: `versions.txt` (app version, .NET, OS, claude version, git hash if known), `setup-check.txt` (rows as text), `preflight.txt`, `app.log` tail (last 500 lines, redacted), `events.tail.txt` (last 200 events, redacted), `settings.txt` (ui.json **keys and non-text values only**: booleans/numbers/choice names; never file contents of library.json or any note text). **Never** `cache\`, transcripts, library.json, runs.json. A test builds the zip from a fixture state folder that contains canary strings in every source (log, events, ui.json, library, cache, a note) and asserts none appears in any zip entry and no forbidden entry exists. Keep only the newest 5 zips. Core `Diagnostics/DiagnosticsBundle.Build(...)` (pure over provided text sources) + App wiring.
- [x] B5. **Launcher and version.** `scripts/Start-OpenTail.Bullshark.bat` starts the newest of the Debug/Release `net10.0-windows10.0.19041.0` builds with **no** demo arguments (a small `%~dp0` search; say clearly if none is built); keep the demo launcher as `scripts\Start-Demo.bat` with the old arguments. Test any pure formatting helper.
