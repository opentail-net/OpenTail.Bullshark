## Contracts this must satisfy

| Member | What it promises / what callers rely on |
|---|---|
| `TrustCheck.Check(folder, claudeJsonPath)` | Repo root found by walking up for `.git` (dir or file). No root → `NotARepository`. Root trusted when the first `projects` entry whose `Normalise`d name equals the `Normalise`d root has `hasTrustDialogAccepted: true`. Used by `FolderCheck` and `TrustGate`; tests in `Trust/TrustCheckTests.cs`. |
| `TrustCheck.IsRecordedTrusted` | Missing file → false. Unreadable or bad JSON → treated as `{}` → false. No `projects` object → false. |
| `TrustCheck.UnreadableProblem` | Missing file → null (not a problem). IO / JSON / access error → a message. |
| `TrustGate.Filter(specs, path)` | Groups specs by `FolderKey.From(WorkingDirectory)` (case-insensitive); checks the first spec's folder per group. `NotTrusted` → root added once to UntrustedRoots, group left out. `Trusted` and `NotARepository` → whole group runnable. |
| `SupervisorRunner.CheckOnceAsync(specs, ct)` | Lists agents first, then loads the store (an unreadable store throws before anything starts). Saves in `finally` through `Merge`. Many tests call it as `CheckOnceAsync(specs)`. |
| `SupervisorLoop.RunPassAsync(specs, ct)` | Runs one runner pass, then reads logs for the login-expiry alert. Returns the action count. |
| `ClaudeCli.ResolveSessionIdAsync(shortId, timeout, ct)` | Polls `agents --json` every second until the short id has a session id; throws `ClaudeCliException` after the timeout. |
| `FileLock.Hold(path)` / `WriteAtomic(path, text)` | Cross-process lock per file (window and supervisor). Write = temp file beside the path, then move over it. |
| `SessionWindow.PassAndRefreshAsync` | Skips if a pass runs. Sets `_storeProblem` from store reads. Shows/hides trust steps, Retry button and status line. No starts while `~/.claude.json` is unreadable or `--no-pass` is set. |

## Items

### 1. Read `~/.claude.json` once per pass (perf + consistency)
Now: `TrustGate.Filter` parses the whole file once per folder group, and `UnreadableProblem` parses it once more; a write between
the two reads makes every folder look untrusted for one pass.

- [ ] Add `ClaudeTrust` (in `Core/Trust`): `static ClaudeTrust Read(string claudeJsonPath)` parses once and holds
  `string? Problem` (same text and same rules as `UnreadableProblem`) and the trusted roots as a dictionary of `Normalise`d name → bool,
  filled with `TryAdd` so the **first** matching entry wins, as today. Missing file → no problem, nothing trusted.
  Unreadable → `Problem` set, nothing trusted. Method `bool IsTrusted(string root)`.
- [ ] Add overloads `TrustCheck.Check(string folder, ClaudeTrust trust)` and `TrustGate.Filter(IEnumerable<SessionSpec>, ClaudeTrust)`.
  The existing path-taking methods call `ClaudeTrust.Read` once and delegate, so `FolderCheck` and existing tests do not change.
- [ ] Tests: every row of the `TrustCheck` / `TrustGate` contract rows above against the new overloads, plus: duplicate entries
  with different case, first wins; unreadable file gives `Problem` and no trusted root.

### 2. Do the pass's I/O off the UI thread (no UI freeze)
Now: `ReadRecords()`/`ReadRuns()` run on the UI thread inside `PassAndRefreshAsync`; `FileLock.Hold` can wait up to 10 s.

- [ ] In `PassAndRefreshAsync`, do in one `Task.Run`: list agents, load records and runs, build specs, `ClaudeTrust.Read`, `TrustGate.Filter`.
  Return a small record with the results and any store problem message. Set `_storeProblem` and touch WPF objects only on the UI thread
  after the await. Keep the rule: no starts while `Problem` is set or `--no-pass`.
- [ ] After the runner pass, count failed starts in the same background step (load records once there), not with `ReadRecords()` on the UI thread.
- [ ] `RefreshRail` gets an optional `IReadOnlyDictionary<string, SessionRecord>? records` parameter; the pass passes the records it
  loaded after the runner ran. Other callers keep calling it without arguments (they still read on the UI thread; out of scope, see below).
- [ ] Logic that can move to Core without WPF goes into a Core class (for example `PassSnapshot`) with unit tests. The WPF part stays thin.

### 3. List agents once per pass
Now: the window lists agents, then `SupervisorRunner.CheckOnceAsync` lists them again (each is a new `claude` process).

- [ ] Add overloads `SupervisorRunner.CheckOnceAsync(IReadOnlyList<SessionSpec> specs, IReadOnlyList<AgentInfo> agents, CancellationToken ct = default)`
  and `SupervisorLoop.RunPassAsync(specs, agents, ct)`. The old signatures list agents themselves and call the new ones. Keep the
  order "agents first, then store load" in both.
- [ ] The window passes the listing from item 2.
- [ ] Test: with a fake runner that counts `agents` calls, the agents overload makes no `agents --json` call for a pass that only adopts/alerts.

### 4. Refuse briefs that the command line cannot carry
Now: `StartBackgroundAsync` passes the prompt as a positional argument. Windows caps a command line at 32,767 characters, and a prompt
starting with `-` would be read as an option.

- [ ] In `StartBackgroundAsync`, before running: if the prompt starts with `-`, or the joined arguments exceed 30,000 characters,
  throw `ClaudeCliException` with a plain message saying which and how long. The runner already records it as a failed start.
- [ ] Tests for both cases and for a normal prompt (argument list unchanged).
- Not done: sending the prompt on stdin. Whether `claude --bg` reads stdin is not verified; owner to decide (see Open items).

### 5. `ResolveSessionIdAsync` uses a `TimeProvider`
- [ ] `ClaudeCli(ICliRunner runner, TimeProvider? clock = null)`; default `TimeProvider.System`. Deadline from `clock.GetUtcNow()`,
  wait with `Task.Delay(TimeSpan.FromSeconds(1), clock, ct)`.
- [ ] Test the timeout without real waiting. No new packages: if the tests have no manual `TimeProvider` subclass yet, write a small one.

### 6. `FileLock` small fixes
- [ ] `Hold`: build the key from `Path.GetFullPath(path).ToUpperInvariant()` on Windows (`OperatingSystem.IsWindows()`), so two spellings
  of one path share a lock. Window and supervisor ship together, so the key change needs no migration.
- [ ] `WriteAtomic`: if the write or the move throws, delete the temp file (ignore errors from the delete) and rethrow.
- [ ] Tests: same path in two cases maps to one lock (hold one, the other times out — use a short wait via an internal overload if needed);
  a failed move leaves no `.tmp` file.
