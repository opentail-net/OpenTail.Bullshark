# Command palette, 2026-11-18 (ideas D3)

Goal: one keyboard box to jump to a session or a page, or run a safe action, without the mouse. Idea from PowerToys Command Palette (select, then
a second key runs) and Raycast (see `ideas-2026-11-18.md`; researcher-reported). Nothing is ever sent to a session (principle 3).

## What exists (read first)

- Status-bar buttons (`SessionWindow.xaml` ~114-130): Timeline, Storage, Limits, Away, and the conditional Trust/Retry/Respawn. Their click handlers open pages (`TimelineButton_Click`, `StorageButton_Click`, `LimitsButton_Click`, `AwayButton_Click`).
- Search box (`SearchBox_KeyDown`, `SessionWindow.Search.cs`): transcript search stays as it is.
- Rail: sessions are `RailTag(RailKind.Session, key)`; selecting one goes through `NoteRailSelection` (`SessionWindow.Tabs.cs`).
- `OnPanePreviewKeyDown` (`SessionWindow.xaml.cs` ~513) already handles zoom keys and paste while a terminal has focus.
- Existing "Library" page, setup tab (`OpenSetupTab`), "pass now"/refresh (find the existing handler of the refresh button; do not duplicate pass logic).

## Contracts this must satisfy

| Member | Promise |
|---|---|
| `OnPanePreviewKeyDown` | Zoom and paste behave exactly as before. The palette adds one chord before them and returns `Handled` only for that chord. |
| Terminal keys | Claude Code's prompt uses Ctrl+K (kill line), Ctrl+P etc. **Do not bind Ctrl+K, Ctrl+P, Ctrl+R, Ctrl+L or plain letters.** Chord: **Ctrl+Shift+P** (works while a terminal has focus; Windows Terminal/VS Code use it too). |
| Principle 3 | No palette entry sends text to a session, answers a prompt, stops, removes or restarts a session. v1 = navigation and safe actions only. |
| Existing handlers | Palette entries call the same code the buttons and rail call; no second implementation of any action. |
| UI thread | Entry list built from in-memory state (rail records, listing); no disk reads when opening. |

## Design decisions (AFK; change if you disagree)

- D1 v1 entries: "Go to session <name>" for each session of the current runs (state shown as the hint, e.g. `blocked`), pages (Timeline, Storage, Limits, Away, Library, Search, New session setup), actions: "Refresh now" (the existing refresh/pass), "Acknowledge all waiting" and "Snooze all waiting 1 hour" (escalation D2: only silence, never answer), "Toggle sound and flash" (ui.json `notify`).
- D2 Destructive things (stop, respawn, remove, archive) are NOT in v1. Recorded as an open item; if added later they need select-then-Ctrl+Enter.
- D3 Matching: case-insensitive; every query word must match as a prefix of a title word or as a subsequence; score prefix > word start > subsequence; ties keep the entry order (sessions that need the owner first, then other sessions, then pages, then actions). Empty query lists the first 12 entries in that order.
- D4 UI: an overlay panel (Popup or a hidden-by-default Grid over the pane; follow what other dialogs in the App do) with a TextBox and a list; Up/Down move, Enter runs, Esc closes and gives the focus back to what had it (a terminal must get its keyboard back). Themed like the rest (`ApplyTheme`, dark and light). At most 12 rows shown.
- D5 A status-bar button "Go to…" (tooltip shows the chord) opens it too, so it is findable.

## Decisions

- **Overlay is a window, not a Grid or a Popup.** A Grid cannot draw over the terminal: the terminal is a native window (`zoom.md`, README "Airspace"). A Popup's keyboard focus could not be checked without a running window. `CommandPaletteWindow` is a borderless window owned by the session window, centred on it, shown with `ShowDialog`, as `ClosePrompt` is.
- **Keyboard return.** The control to return to is the terminal whose native window had focus (`NativeFocusedTerminal`), else the last shown visible terminal, else the WPF-focused control. Esc returns it. An action that leaves the pane as it is (refresh, acknowledge, snooze, toggle) returns it after it runs. A navigation sets its own focus (`ShowOnly`, or the search box) and is not overridden.
- **The chord opens the palette after the key is finished** (`Dispatcher.BeginInvoke`, Input priority), so no window is shown from inside the key handler. It is checked before the zoom, and only Ctrl+Shift+P is taken there. Zoom and paste are unchanged.
- **Library.** The window has no Library page. The entry "Show archived sessions (Library)" sets the rail filter to Archived through `ChooseFilter`, the rail's own handler.
- **Search.** "Search what was said" puts focus in the rail's search box, opening the rail first when it is hidden. It does not start a search.
- **Refresh now** runs `PassAndRefreshAsync`, the same pass as the 15-second timer. That pass can start or resume sessions as it does every 15 seconds. This is the existing pass the plan names, not a new action. If the owner wants a refresh that never runs the supervisor, that needs a rail-only refresh (open item).
- **Session entries** come from the rail's last refresh (`_railRecords`), so opening reads no file. Sessions that wait for the owner (their names are in the Needs-you list) come first, then the others, by name. A session in its own window is left out, since its terminal is not in this window. The hint is the listing state with the waiting reason (`StateWithWaiting`), for example "blocked · waiting for permission prompt". Going to a session shows its tab, reopening it if the owner had closed it, as a tab click does.
- **Acknowledge and snooze** are listed only when the Needs-you list holds an escalating item (blocked, restart loop, start failed, stopped, failed). They call `AcknowledgeNeed` and `SnoozeNeed`, as the row menu does, for each such session.
- **Sound and flash.** The toggle reads ui.json `notify` when it is chosen, not when the palette opens, writes the flipped value, and reads it back for the status line. The entry has no hint, so opening reads nothing.
- **Matching** follows the rules in the class summary of `CommandPalette`: a word scores 3 when the title starts with it, 2 when a word of the title does, 1 when its letters come in order; an entry's score is its lowest word score. Accents are not folded, so "cafe" does not find "Café". Folding can come later; the rule is the simpler one for now.
- **Groups** (the Order number): 0 waiting sessions, 1 other sessions, 2 pages, 3 actions.
- **Open palette and last-seen.** Opening the palette deactivates the window, so the existing last-seen write to ui.json runs, as it does on any window switch. Nothing else is written on open.
- **Button.** "Go to..." sits with the page buttons; its tooltip gives the chord.
- The README lists no keyboard shortcuts, so it was not changed.
