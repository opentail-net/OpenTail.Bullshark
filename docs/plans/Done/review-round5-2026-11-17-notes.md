# Review round 5: 7a18376..af884a3 (read-only, by reading the lines; nothing run)

1. SupervisorPolicy.cs:136-149 (confirmed). A session listed as stopped/failed gets only an alert (lines ~164-177), "never brought back". But the Gone branch (agent is null) never looks at LastState/LastAlert. Scenario: owner stops a coder, then removes it (claude rm), or `--all` stops listing it; next pass agent is null, restarts < 3, so Resume runs: a paid session the owner stopped. AttentionList.ReasonFor (not-listed branch) assumes the supervisor did not resume it. Fix: in the Gone branch return [] when LastState or LastAlert says stopped/failed.
2. RunBudget.cs:65 + SupervisorPolicy.cs:127 (confirmed). Elapsed is measured from run.CreatedAt, not StartAt. Scenario: run created 14:00, StartAt 18:00, limit 60 min. At 18:00 fraction is 4.0, Reached, and Decide returns [] for the first Start (record is null) with no alert (alerts need a SessionId), so the run never starts, silently. "Start now" does not reset it either. Fix: elapsed from max(CreatedAt, StartAt), and move the origin on StartingNow.
3. AttentionList.cs:116 (confirmed). `waiting` holds the names of ALL previous items, notices included. A session with a standing Overlap/Conflict notice that later becomes Blocked/Stopped/Failed/StartFailed is not "new", so no sound/flash for the very event Needs-you exists for. Fix: build `waiting` only from non-notice items.
4. AttentionList.cs:194 OverlapItems + SessionWindow.Overlap.cs:35 (confirmed). Clashes are computed for every run in runs.json, forever, with no check that the sessions are still live. A finished run's overlap keeps those sessions in Needs you permanently (count never clears, no dismiss). Also SessionWindow.Merge.cs:38 drops the merge result when a coder leaves `done`, so each working->done cycle re-adds the Conflict notice and `Gained` rings and flashes again (plausible). Fix: only report clashes for sessions still live, or add a dismiss; keep the merge result until HEAD changes.
5. SupervisorRunner.cs:96,103 (confirmed). Emit/Write (line ~149) catches only IOException/UnauthorizedAccessException, but EventLog.Write takes FileLock.Hold, which throws TimeoutException (10 s). For Start/Resume this lands in the broad catch at line ~98 AFTER Carry succeeded: Failed() overwrites the good record with an empty-id "start failed" (Start) or adds a bogus restart + LastAlert (Resume); for Alert/Adopt the exception aborts the pass. A started paid session is then shown as failed until the next pass adopts it by name. Fix: catch TimeoutException (any non-cancel exception) in SupervisorRunner.Write.
6. FileOverlap.cs:125-128 SessionWritesCache (confirmed). Any change of length/stamp triggers a full TranscriptReader.ReadFile (JsonDocument per line, whole file). A working session's transcript grows every pass, so each 15 s pass re-parses the entire file for every working session, and the first pass parses every old session of every run. With 100s of MB this is constant CPU/IO and delays the pass. Fix: read incrementally from the previous length, or only for runs that have 2+ sessions or a limit.
7. TimelineView.cs Draw (~line 125-130) (construction confirmed, size plausible). One TextBlock per event in a ListBox inside a ScrollViewer, so no UI virtualization; ApplyTheme also calls Draw. The log holds up to ~10 MB (tens of thousands of events); Show/Draw runs on the UI thread and can freeze it for seconds. Lines carry no date (HH:mm:ss) and events carry no run id, so a reused name shows another run's events. Fix: drop the outer ScrollViewer so the ListBox virtualizes, or show the last N events and filter by run CreatedAt.
8. SessionWindow.Storage.cs:64-68 (plausible). Protection comes from `_allAgents`, which is [] until the first pass completes and stays stale if the pass listing failed. Open Storage in the first seconds and a listed session is not protected; Archive then moves its live transcript (Windows allows it if claude opened it with FileShare.Delete, and claude then recreates the file at the old path: split transcript). There is also no "recently written" guard. Fix: refuse to archive until `_allAgents` has been filled once, and refuse files written in the last N minutes.
9. SessionWindow.Changes.cs:75 (confirmed). WrittenFiles catches only IOException; TranscriptFile.Open throws UnauthorizedAccessException (not an IOException) for a denied file. It escapes Task.Run in ShowChangesAsync (called as `_ = ...`), so the tab stays on "Reading the changes..." with Refresh disabled (ShowLoading set IsEnabled=false). Fix: catch IOException or UnauthorizedAccessException there, and wrap the whole Task.Run body.
10. SessionWindow.Storage.cs:35-43 (confirmed). RefreshStorageAsync/ShowProjectAsync have no try/catch: StorageReport.FilesOf and TranscriptArchive.List (UnauthorizedAccess on any archive subfolder, folder removed mid-enumeration) throw into a discarded task; the page silently shows stale data. After Archive/Restore the middle "Transcripts in <project>" list is not refreshed (only ShowProjects is), so moved files stay checkable and report "The file is gone." Fix: try/catch with SetResult, and re-run ShowProjectAsync for the chosen folder.
11. EventLog.cs:56-62 (plausible). Write appends after a partial last line (a crash mid-write, which the Read comment says is expected) without checking that the file ends in "\n", so the next event is glued onto the partial line and both are dropped when reading. Fix: if the file does not end with \n, write "\n" first.
12. ClaudeCli.cs:86,113 + ResumeText.Fit (plausible). The 30,000 limit counts raw characters; .NET quotes/escapes the argument list (each `"` becomes `\"`, backslash runs doubled before quotes). A resume tail with code or JSON (thousands of quotes) fitted to exactly 30,000 can exceed 32,767 once escaped, so Process.Start throws and the resume run is a StartFailed. The 2,767 margin assumes few quotes. Fix: measure the escaped length in CommandLineLength.
13. SupervisorPolicy.cs LimitNear/LimitReached (plausible, low). HasAlert depends on LastAlert still starting with "LimitNear: "; any other alert (Blocked, RestartLoop) or a Resume (LastAlert=null) overwrites it, so the limit alert and its timeline event repeat. And plan decision additions D4.4 (limit notices not in Needs you, no announcement) means a run that hits its limit and stops resuming sessions is visible only in the log/timeline. Fix: keep a separate limit-level field and surface LimitReached in Needs you.
14. StartTime.cs:35 (plausible, low). `at.AddDays(1)` keeps today's UTC offset; if DST changes in between, the run starts an hour off. Fix: build tomorrow's local DateTime, then take its offset from TimeZoneInfo.Local. The waiting rail row (SessionWindow.Schedule.cs) also shows only HH:mm, no date.
15. InstructionFiles.WithLineEnding / InstructionsDialog.Save (plausible, low). A file with mixed endings is rewritten to a single ending, and a lone `\r` becomes a line break, on any save even if the owner edited one line (round3 item 12 decision: majority wins). Fix: normalise only when needed, or preserve per-line endings.
