## Decisions made while building

- Item 1: the closed session's tokens are read before `claude stop`, as the plan says. A still-running session can write a few more tokens between that read and the stop; they are not counted (a small undercount, accepted).
- Item 1: a transcript that exists but cannot be read stops the close ("Not closed: ... transcript could not be read"), because its tokens would be lost from the spend. A session with no transcript file has written none and closes as before.
- Item 1: a run left with no session is dropped with its carried start and tokens, as the reviewer said (fine: the run is gone).
- Item 1: the records-less `RunSpend.ElapsedOf(run, now)` also starts from `FirstStartedAt` when set. No App caller uses it; it is kept consistent with the spend.
- Item 1: `RunRecord` got the two fields as trailing optional parameters, and `WithoutSession` got two optional parameters, so every existing call still compiles.
- Item 2: the hold is read per action, just before `Carry`. Not done: the window's Respawn click does not wait for a pass that is already running. An action that passed its check just before the click can still be launched while the respawn starts. The window is one process launch long, and the review's optional fix (the click waiting for the pass) needs a UI-thread change, so it is left for the owner.
- Item 3: the status is read twice, before and after the listings, as the plan says; the rule is `DaemonStatus.Around` (Core, tested for both orders). The App's `ReadForPassAsync` is not unit-testable, so it is checked by reading the code and by the screen script. The cost is one more `claude daemon status` process per pass (every 15 seconds).
- Item 3: when the reads disagree (one running, one not, or one unknown), the rows are live; the pass shows the running read's version and text, else the later read's text.
