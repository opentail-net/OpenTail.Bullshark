## Contracts this must satisfy

| Member | What it promises / what callers rely on |
|---|---|
| `FileLock.Hold` / `WriteAtomic` | Cross-process lock per file; temp file with a unique name, then move. The stores for runs, state, library and tab order already use it. |
| `TranscriptFile.Open` / `ReadLines` | The one way to open a transcript (share ReadWrite + Delete). |
| `TranscriptLine.From(number, json)` | Parses one transcript line into what the view shows; `Text` is unescaped. |
| `ClaudeCli.StartBackgroundAsync` | Refuses a prompt starting with `-` or a command line over 30,000 characters (`ClaudeCliException`). |

| `App.DispatcherUnhandledException` | Logs and marks handled: UI exceptions become silent failures, not crashes, so every user action must report its own failure. |

## Decisions made while building

- Item 1: a word is pre-filtered only when every character is an ASCII letter, digit, `-`, `_` or `.` (`HistorySearch.SameInRawLine`). A word with a backslash, a quote or any other character is parsed in every line, so a Windows-path search is slower than a plain-word search; the speed path is kept for plain words.
- Item 3: the SetupView catch also takes `ArgumentException` and `NotSupportedException`, because `FolderKey.From` throws them for a hand-edited run path; `FolderSuggestions.Build` now also skips such a run (Core test). `App.OnStartup` keeps its `ArgumentException` branch (exit 2) and adds a general one (log, message box, exit 1).
- Item 4: the old test "a corrupt file gives the defaults" asserted the behaviour this item removes; it is replaced by "not read as empty and not overwritten". Two more callers (the resume's solo settings, SessionWindow.Resume.cs) fall back to the defaults on a bad file, because a resume writes no pattern. A file that exists but cannot be read is a store error, not a missing file (`File.Exists` is not used to decide "missing").
- Item 5: a resume whose id is not read back in time is recorded with no session id, and with `RunPlan.PendingIdAlert` as its alert (so the attention list does not call a running session "start failed" without a reason); the next pass adopts it by name (tested through `SupervisorPolicy.Decide`). The status line says "started; the session id will be picked up on the next pass". The guard is a flag in `ResumeAsync`, which wraps `ResumeOnceAsync`; the Resume button is off while it runs (`TranscriptView.SetResumeBusy`).
- Item 6: `ClaudeCli.MaxLaunchCharacters` was already public, so it is used as it is. The check is exact: `SetupPlan.LongestCommandLine` builds the run's specs as the run will (run id of four characters) and measures each launch with `ClaudeCli.CommandLineLength`, the same count `StartBackgroundAsync` refuses on. `ResumeText.Fit` cuts the excess out of the tail; older turns go first (as with the token cap), then the latest turn is cut in its middle. The status line says how many characters were cut; a text still over the limit is refused before the run is written.
- Item 7: no unit test (the catch is in the window, and the plan names no Core part). The catch is on the wrapper, so it covers the resume prompt, the source read and the summary; the callers keep `_ = ResumeAsync(...)`.
- Item 8: the logic moved to Core (`Core/Ui/UiSettingsFile.cs`, with tests), and `UiFile` is now a thin wrapper that logs through `AppLog`. `ThemeStore.Load` read ui.json with its own unlocked parser that never recovered a damaged file; it now reads through `UiFile`. A file that cannot be read (held by another process) is not moved aside: only one that does not parse is. An older `ui.json.bad` is replaced.
- Item 9: a settings.json or .claude.json whose root is not an object is a Problem item, and the check goes on (it used to stop). A hook group or hook that is not an object is a Problem item ("the entry is not an object"), like an MCP entry that is not one. Other odd shapes that are not objects are skipped, as before.
- Item 2: no unit test (the guard is a counter, checked by reading). The lineage of the pane is drawn only when the pane still shows that session (`TranscriptView.IsShowing`): the rail and the search both drew it after the await, so a stale call could repaint another session's lineage.
