## Contracts this must satisfy

| Member | What it promises / what callers rely on |
|---|---|
| `FileLock.Hold` / `WriteAtomic` | Cross-process lock per file; temp file with a unique name, then move. The stores for runs, state, library and tab order already use it. |
| `TranscriptFile.Open` / `ReadLines` | The one way to open a transcript (share ReadWrite + Delete). |
| `TranscriptLine.From(number, json)` | Parses one transcript line into what the view shows; `Text` is unescaped. |
| `ClaudeCli.StartBackgroundAsync` | Refuses a prompt starting with `-` or a command line over 30,000 characters (`ClaudeCliException`). |
| `SupervisorPolicy` adoption | A listed session of the run's name that is not `stopped`/`failed` is adopted when the record is missing. |
| `App.DispatcherUnhandledException` | Logs and marks handled: UI exceptions become silent failures, not crashes, so every user action must report its own failure. |

## Items

### 1. Search finds words with `\` or `"` (R1)
- [ ] The pre-filter at HistorySearch.cs:116 tests the raw JSON line, where `\` is `\\` and `"` is `\"`. Test the word in its JSON-escaped form too (`JsonEncodedText`-style escaping of the word, compared case-insensitively), or drop the pre-filter for words that contain those characters. Keep the pre-filter for plain words (it is the speed path).
- [ ] Tests: a Windows path and a quoted phrase are found; a plain word still uses the fast path.

### 2. The transcript view shows the latest selection only (R2)
- [ ] `TranscriptView.ShowAsync`: a version counter (or token) taken before the await; after each await, return if a newer call started. Same guard for any later await in that method.
- [ ] Core-testable part: none needed if the guard is two lines; record that the check is by reading.

### 3. Startup survives a bad or locked runs.json (R3)
- [ ] `SetupView` constructor: catch `StoreUnreadableException`, `TimeoutException`, `IOException`, `UnauthorizedAccessException` around the runs load; use an empty list and log it. The window must open.
- [ ] Also widen `App.OnStartup`'s catch to log and show a message box for any exception, instead of exiting silently.

### 4. Pattern store: locked, atomic, no silent wipe (R4)
- [ ] `PatternStore` read and write under `FileLock.Hold`, write through `FileLock.WriteAtomic`, read again under the lock before changing one pattern (like `StateStore.Update`).
- [ ] An unreadable patterns.json throws a store-unreadable error and is never overwritten; the setup page shows the message.
- [ ] Tests: two writers keep both patterns; a corrupt file is not overwritten; IO errors surface as the store error.

### 5. Full resume: no orphan session (R5)
- [ ] When the start succeeds and the id read-back times out, write the record with no session id but with the name, as the supervisor does for a failed start, so the next pass adopts it by name (adoption already handles this). Report "started; the session id will be picked up on the next pass".
- [ ] Guard against a second click while one resume is in flight (disable the button until it finishes).
- [ ] Tests for the Core part (record shape) if any logic moves to Core.

### 6. Resume text fits the command line (R6)
- [ ] Before writing the run, check the resume brief against the same limit `StartBackgroundAsync` uses (expose the limit as a public constant). Too long → cut the last turn's text from the middle with a marker (`… [cut N characters] …`), keeping its start and end; report it in the status line.
- [ ] Tests: a huge last turn is cut under the limit; a normal one is unchanged.

### 7. Resume failures are reported (R7)
- [ ] Wrap the body of `ResumeAsync` in a catch for any exception: log it, set the status line to "Not resumed: <message>", and clear the busy state. Keep `_ = ResumeAsync(...)` callers, or make them await.

### 8. ui.json: atomic, locked, recoverable (R8)
- [ ] `UiFile` writes through `FileLock.Hold` + `WriteAtomic`. A truncated or invalid ui.json is moved aside to `ui.json.bad` (once, logged) and treated as empty, so later saves work again.
- [ ] Tests (Core, if `UiFile` logic can move to Core; else record why not).

### 9. Setup check survives odd JSON shapes (R9)
- [ ] Guard every `TryGetProperty` in SetupCheck.cs with a `ValueKind == Object` check, as `ClaudeTrust` and `TrustCheck.TrustedRepositories` already do. Tests with `[]`, a string, and an entry that is not an object.

### 10. Library errors are shown; a null entry does not break it (R10)
- [ ] Add `UnauthorizedAccessException` to the catches at Library.cs:44, :109 and Resume.cs:312, and show the message in the status line.
- [ ] `SessionLibrary` read skips null entries (log once). Test with a library.json holding a null value.

### 11. Setup page does not re-read ~/.claude.json on every key (R11)
- [ ] Read `ClaudeTrust` once when the page opens and on folder change (debounced 300 ms), not per keystroke; `Refresh` uses the cached value.

### 12. Instructions dialog: no wrong-file save, keep line endings (R12)
- [ ] `Open` sets `_current`/`_stamp` only after a successful read; on failure, keep the previous file and show the error.
- [ ] Remember the file's line ending (LF or CRLF, by majority) and write with it. Tests on the Core helper that detects and restores line endings.

### 13. ResumeSource opens transcripts the shared way (R13)
- [ ] Replace `new StreamReader(path)` at ResumeSource.cs:25 with `TranscriptFile.Open`.

### 14. Setup check: hooks with variables, CLAUDE_CONFIG_DIR (R14)
- [ ] A hook command whose program part starts with `$` or `%` or contains `${` is reported as "uses a variable; not checked", not "not found".
- [ ] CLAUDE_CONFIG_DIR: not verified where Claude keeps `.claude.json` then. Record as open; do not change.

### 15. Supervisor host and stale docs (R15)
- [ ] Add top-level error handling to the Supervisor `Program.cs` (log and exit code 1).
- [ ] Fix the `FileLock` doc comment that says the window and the supervisor both write the files: today only the window writes; the host only reads. Note in README Architecture that the headless host is report-only for now (the log-on supervisor of P4 is not built).

### 16. Search housekeeping (R16)
