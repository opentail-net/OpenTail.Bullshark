## Goal

The Limits page and the Away digest read Codex usage too (the App passes the Codex history folder and the usage settings to
`LimitHistory.ReadReportWithCache`). The Codex rollouts are cached in memory between reads, so the two readers share one read of
each finished rollout. The page says how many rollouts this build could not read (the compressed ones on net10.0).

## Contracts this must satisfy

- **Memo reuse equals a fresh read.** For the same file, same length, same write time, same `reasoningAsOutput`, and an old enough
  write time, a reused record equals what `ReadFile` gives now. Tested as a differential (reuse against a fresh read).
- **Memo does not change Claude.** The Claude transcript reads, the Claude cache (`LimitHistoryCache`) and `LimitHits` are not touched.
- **`LimitsReport` keeps its members and constructor.** `CodexSkipped` is added last, with default 0, so the existing three-argument
  construction and every existing reader of the record compile and behave as before. The only `new LimitsReport(` call site is in
  `LimitHistory.ReadReportWithCache`.
- **`ReadFolder` keeps its records.** Its result is `CodexUsageRead(Records, Skipped, Unreadable)`; `Records` is the list the old
  return value gave, in the same order and with the same content.
- **Thread safety.** The Limits page and the Away digest run on pool threads and may overlap, so the memo locks its own state.
- **Unchanged Claude numbers.** Passing the memo or the settings does not change a Claude number: the Claude read is the same call.

## Decisions

1. **Both callers pass the usage settings and the Codex history root.** The root is `(_codex ?? new CodexProvider()).Paths.HistoryRoot`
   read on the UI thread before `Task.Run` (the window's Codex provider accessor; `_codex` is not assigned here, so the rail's provider
   choice is unchanged). The settings are `_behaviour.Usage`, read on the UI thread too.
2. **The memo.** `CodexUsageMemo` (Core, public, one per window, not static). Keyed by the rollout's full path. An entry holds the
   file's length, its last write time (ticks), the `reasoningAsOutput` the record was read with, and the record (null for "no valid
   total"). An entry is reused when length, write time and `reasoningAsOutput` are equal, and the file is not live (its write time is
   more than 2 minutes before `now`). A file that failed to read is not kept (its old entry is removed). Entries of files that are no
   longer in the folder are removed on each `ReadFolder` call.
3. **Skipped and unreadable.** `ReadFolder` returns `CodexUsageRead(Records, Skipped, Unreadable)`. `Skipped` is the count of compressed
   rollouts this build cannot decode. `Unreadable` is the count of files that failed to open, read or stat. `LimitsReport.CodexSkipped`
   carries `Skipped` only, because the owner's note text is about compressed files. `Unreadable` is logged (counts only) and not shown.
4. **The note.** `LimitsView` shows one line under the usage section when `CodexSkipped > 0`: "N Codex rollouts not read: this build
   cannot decode compressed files." with N the count. Always the word "rollouts" (the owner's wording). Hidden when 0.
5. **Away.** The same call with the same settings, root and memo. Away's digest is not changed; only `report.Usage` feeds it, as now.
6. **Project names** are unchanged (part 1).
7. **Seams for tests.** `ReadFolder` takes two optional parameters: `now` (for the live-file rule; default `DateTimeOffset.UtcNow`)
   and `canDecodeCompressed` (default `RolloutReader.CanDecodeCompressed`). The second lets a net11.0 test run the net10.0 skip path.
8. **The memo is pruned on each read.** A memo that is never pruned grows with every rollout the owner ever had. Pruning on the
   folder listing keeps only the files that are there, which is the set both callers read.
