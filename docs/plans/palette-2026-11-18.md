# Command palette, 2026-11-18 (ideas D3)

Goal: one keyboard box to jump to a session or a page, or run a safe action, without the mouse. Idea from PowerToys Command Palette (select, then
a second key runs) and Raycast (see `ideas-2026-11-18.md`; researcher-reported). Nothing is ever sent to a session (principle 3).

## What exists (read first)

- Status-bar buttons (`SessionWindow.xaml` ~114-130): Timeline, Storage, Limits, Away, and the conditional Trust/Retry/Respawn. Their click handlers open pages (`TimelineButton_Click`, `StorageButton_Click`, `LimitsButton_Click`, `AwayButton_Click`).
- Search box (`SearchBox_KeyDown`, `SessionWindow.Search.cs`): transcript search stays as it is.
- Rail: sessions are `RailTag(RailKind.Session, key)`; selecting one goes through `NoteRailSelection` (`SessionWindow.Tabs.cs`).
- `OnPanePreviewKeyDown` (`SessionWindow.xaml.cs` ~513) already handles zoom keys and paste while a terminal has focus.
- Existing "Library" page, setup tab (`OpenSetupTab`), "pass now"/refresh (find the existing handler of the refresh button; do not duplicate pass logic).

## Contracts this must satisfy

| Member | Promise |
|---|---|
| `OnPanePreviewKeyDown` | Zoom and paste behave exactly as before. The palette adds one chord before them and returns `Handled` only for that chord. |
| Terminal keys | Claude Code's prompt uses Ctrl+K (kill line), Ctrl+P etc. **Do not bind Ctrl+K, Ctrl+P, Ctrl+R, Ctrl+L or plain letters.** Chord: **Ctrl+Shift+P** (works while a terminal has focus; Windows Terminal/VS Code use it too). |
| Principle 3 | No palette entry sends text to a session, answers a prompt, stops, removes or restarts a session. v1 = navigation and safe actions only. |
| Existing handlers | Palette entries call the same code the buttons and rail call; no second implementation of any action. |
| UI thread | Entry list built from in-memory state (rail records, listing); no disk reads when opening. |

## Design decisions (AFK; change if you disagree)

- D1 v1 entries: "Go to session <name>" for each session of the current runs (state shown as the hint, e.g. `blocked`), pages (Timeline, Storage, Limits, Away, Library, Search, New session setup), actions: "Refresh now" (the existing refresh/pass), "Acknowledge all waiting" and "Snooze all waiting 1 hour" (escalation D2: only silence, never answer), "Toggle sound and flash" (ui.json `notify`).
- D2 Destructive things (stop, respawn, remove, archive) are NOT in v1. Recorded as an open item; if added later they need select-then-Ctrl+Enter.
- D3 Matching: case-insensitive; every query word must match as a prefix of a title word or as a subsequence; score prefix > word start > subsequence; ties keep the entry order (sessions that need the owner first, then other sessions, then pages, then actions). Empty query lists the first 12 entries in that order.
- D4 UI: an overlay panel (Popup or a hidden-by-default Grid over the pane; follow what other dialogs in the App do) with a TextBox and a list; Up/Down move, Enter runs, Esc closes and gives the focus back to what had it (a terminal must get its keyboard back). Themed like the rest (`ApplyTheme`, dark and light). At most 12 rows shown.
- D5 A status-bar button "Go to…" (tooltip shows the chord) opens it too, so it is findable.
