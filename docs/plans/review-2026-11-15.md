## 2. Where the two stores disagree

Only the session name joins them. There is no lock and no single writer. The pass saves its whole snapshot (Core/Supervisor/SupervisorRunner.cs:44, 79) while the UI thread writes too.

| State | How it arises | Result now |
|---|---|---|
| spec, no record | new run; record lost in a race | Start, a duplicate if the session already runs |
| record, no spec | close race; crash between the two writes | "Other sessions", never supervised |
| record, empty id | failed start or id not read back | no retry; the real session may run unrecorded |
| record, not listed | died, `rm`, daemon restart | Resume with a paid prompt, for every past run |
| listed name, no record | any of the above | invisible; a Start duplicates it |

## 6. Plan

### Phase 1: no lost writes, no surprise sessions

Goal: the files cannot lose an update, and no fault starts a second session.

- [x] One `Update(change)` per store, under a named mutex, with a unique temp name. The pass applies its own records, not its snapshot. Replace every Load-then-Save pair (finding 2). Code: `FileLock`, `StateStore.Update`, `RunStore.Update`, `SupervisorRunner.Merge`.
- [x] Runner: any exception from Start or Resume becomes `Failed`. `Program.cs` catches all (1). Code: `SupervisorRunner.cs:69-72`, the pass catch in `Program.cs`.
- [x] Policy: adopt by name before Start (4). Code: `SupervisorPolicy.cs:58-65`.
- [x] No `[` is a failure, not an empty list (5). Code: `AgentInfo.cs:29-35`. Bad JSON in a store stops the pass with `StoreUnreadableException` and a log line (6). Bad JSON in `~/.claude.json` counts as untrusted: nothing starts, but the log says "waiting for trust", not that the file is unreadable. The plan said "skips the pass with a message": a small gap, open.
- [x] Close: list first, stop a listed session unless it is idle, catch all, put back what a failed stop took out. A closed tab stays closed (7, 8). On 2026-11-16 the status line was fixed: it said "Stopped" for an idle or unlisted session that had not been stopped. The plan's rule was "stop unless unlisted"; question 6 decides whether idle sessions are stopped too.
- [ ] Resume: solo restart prompt (9), refuse a listed session (10), drop "ask one short question" and cap the summary at 6000 characters (11): all met. Not as written: "one write for run and record" cannot be one write, because the record and the run are two files. The record is written first, and a failed run write is logged with the status line. Partly met; the rest is a design limit.
- [x] Arm the timeout before the stdin write; kill the process tree on timeout or cancel (14). Code: `CliRunner.cs:66-92`.
- [x] Logs follow `--state`; `--state` with no value is an error (16). Code: `App.xaml.cs:17-18`, the window's option parse (`SessionWindow.xaml.cs`), the supervisor's option parse.
- [x] Disable Start until the run is written (19). Code: `SetupView.xaml.cs` `Start_Click` and `RunFinished`.
