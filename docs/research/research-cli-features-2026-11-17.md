# Claude Code CLI features useful to Bullshark (claude 2.1.326, researched 2026-11-17)

Confidence tags: [local] = seen in local `claude ... --help` or local `agents --json` output; [docs] = official docs page only (fetched via summarising WebFetch, so quotes are as returned, not byte-checked). No third-party sources used. The changelog page is huge (1.3M chars); only 2.1.323-2.1.326 (Nov 12-16) were read, so the May-Oct history is NOT covered by the changelog; version numbers below come from the agent-view and hooks pages.

## 1. `agents --json` contract and state vocabulary  [local + docs]
- https://code.claude.com/docs/en/agent-view . Fields: always `cwd`, `kind` (interactive|background), `startedAt` (unix ms); background: `id` (short), `state` = working|blocked|done|failed|stopped; while process alive: `pid`, `status` = busy|waiting|idle; when waiting: `waitingFor` = "permission prompt" | "input needed" | "sandbox request" | "worker request" | "dialog open"; when set: `sessionId`, `name`. Local output confirmed: id, cwd, kind, startedAt, sessionId, name, state (no pid/status on exited ones).
- Docs: `--json` lists "every live session, plus background sessions that are still working or blocked even when their process has exited"; `--all` adds completed; `--cwd <path>` filters. Note `done` = turn finished, ready for next prompt (not "completed forever"). Changelog 2.1.326: "JSON output is unchanged" by message rewording.
- Use: map `blocked` + `waitingFor` to distinct badges (permission vs question vs sandbox vs dialog); treat `done` as idle/reusable; do not infer from process liveness. Docs warn to poll this, not parse `~/.claude/jobs/<id>/state.json` (values are overwritten).
- Caveat: `--add-dir`/`--mcp-config` must come after `agents` or `agents --json` errors.

## 2. Notification hook types `agent_needs_input` / `agent_completed` (+ `quota_auto_resume_*`)  [docs]
- https://code.claude.com/docs/en/hooks : Notification matcher values include `permission_prompt, idle_prompt, agent_needs_input, agent_completed, quota_auto_resume_fired, quota_auto_resume_stale, quota_auto_resume_disabled, elicitation_*`. Agent view says these fire "while agent view is open" for local background sessions.
- Use: push-style "needs input / finished" instead of polling, via an HTTP hook to a Bullshark localhost listener (see item 3). Caveat: tied to agent view being open per the docs, so keep polling as fallback. `quota_auto_resume_*` signals a session waiting out a usage limit - surface as "paused on limit".

## 3. HTTP hooks and supervision-relevant hook events  [docs]
- Hook type `http` POSTs the event JSON to a URL; handlers: command|http|mcp_tool|prompt|agent. `onFailure: continue|block` needs v2.1.295. Admin controls `allowedHttpHookUrls`, `httpHookAllowedEnvVars`. Common input fields: `session_id`, `transcript_path` (written asynchronously, may lag), `cwd`, `hook_event_name`, `prompt_id`, `permission_mode`, `scratchpad_dir` (v2.1.257).
- Useful events: `Stop`, `StopFailure` (API error end of turn), `PermissionRequest`/`PermissionDenied`, `SubagentStart/Stop`, `TaskCreated/Completed`, `PostToolUse` (file-overlap detection live instead of transcript tailing), `FileChanged`, `CwdChanged`, `WorktreeCreate/Remove`, `PreCompact/PostCompact`, `PostModelSwitch`, `SessionStart` (matcher startup|resume|clear|compact|fork), `SessionEnd`. 33 events listed.
- Use: a Bullshark-owned hooks settings file passed per run via `--settings` (agents/--bg pass it to dispatched sessions) gives real-time events keyed by `session_id` without touching user settings. Caveat: hooks do not run under `--bare`; `PreToolUse` "decision: block" semantics tightened in 2.1.326 ("may start blocking calls"). Also `PreToolUse` could implement the run-limit/overlap gate as a block, not just an alert.

## 4. Peek/reply semantics: how to message a background session  [docs]
- No `claude send` CLI exists locally (subcommand list: agents, attach, logs, stop, rm, respawn, daemon, ...). Docs: replies from agent view peek join the session's queue while working ("join the session's message queue instead of interrupting"); `/model`, `/effort`, `/rename`, `/usage` run immediately; exact `/stop` stops it; a permission prompt/dialog is NOT answered by a reply ("Your message waits in the queue. To answer the dialog, attach"). `!`/`/`-prefixed undelivered replies are never saved. Replying to an exited session (`∙`) restarts it from saved conversation.
- Use: Bullshark's embedded-terminal attach remains the only way to answer permission dialogs; for plain nudges, `claude --resume <full-sessionId> --bg` (local help: "continues that session in the background under the same ID, or starts a copy and says so when the session is already running") is the scriptable route. Caveat: `--continue`/bare `--resume`/resume-by-name always start a copy (add `--fork-session` intentionally); copies would show up as new rows with the same transcript lineage.

## 5. `claude respawn <id>|--all` and `claude daemon status|logs|stop [--keep-workers]`  [local + docs]
- Local help: "respawn: Restart a background session, or all of them with --all, so it runs the current Claude Code version". `daemon status` prints "pid, version, uptime"; docs: warns when supervisor version differs from `claude`; files `~/.claude/daemon.log`, `~/.claude/daemon/roster.json`; local help: "Service install is disabled in this version - the daemon runs on demand and exits once no client is connected and no background session is running". Idle sessions stop after ~1 hour (pin with Ctrl+T in agent view); exited sessions show `∙` and restart on reply.
- Use: a "version drift / restart onto new binary" banner and action; show daemon health; explain why an idle tab's process vanished (state stays `done`, process gone, `pid` absent). Caveat: `daemon stop` terminates all sessions - never offer without confirmation.

## 6. `claude rm` safety protocol and worktree handling for --bg  [local + docs]
- Local help: `claude rm <id> [--discard-unpushed <commit>@<worktree-id>] [--force-remove-worktree <worktree-id>]`; "If it's safe, remove ... and delete its worktree. Its conversation is kept". Docs: flags need v2.1.260 / v2.1.268; the values come from the refusal message of a previous `claude rm <id>` run; unpushed commits block deletion; uncommitted changes keep the worktree (agent view Ctrl+X x2 deletes them anyway).
- Docs: dispatched sessions auto-move into `.claude/worktrees/` before editing unless backgrounded via `←`//background, already in a linked worktree, non-git dir (no isolation), or `worktree.bgIsolation: "none"`. Non-git dirs: parallel sessions can collide. Sessions commit+push, open draft PRs, never push to main/master.
- Use: remove-with-confirmation dialog that parses the refusal (commit@worktree-id) and shows unpushed work; file-overlap alerts should compare worktree paths (cwd of session may be the original repo while edits land in `.claude/worktrees/*`); merge-conflict alert can rely on the PR/branch the session pushes. Caveat: parse of refusal text is not a documented machine format.

## 7. Session names, `--name`, attach/logs by name, `n:` filter  [local + docs]
- Local help: `-n, --name`; `attach <id|name>` "Part of the session name works too"; `logs <id|name>`. Docs: names auto-generated by a Haiku-class model from the prompt (or plan title); `--name` overrides; `/rename` persists across restarts; duplicate `/bg` names get "(2)"; attach/logs by name needs v2.1.290; name lookup for attach only while the process runs; `n:` filter v2.1.287.
- Use: pass `--name` on every dispatch (scheduled runs: stable prefix) so tabs, `--resume <name>` and archive entries correlate; re-read `name` from `agents --json` each poll since it changes (auto-title, /rename). Caveat: names are not unique; key on `sessionId`.

## 8. `claude --bg` flags: `--exec`, `--safe-mode`, `--restricted`, `--agent`, `--effort`, `--permission-mode`, `--settings`, `--worktree`  [local + docs]
- Local help shows `--effort <level> (low, medium, high, xhigh, max)`, `--permission-mode (acceptEdits, auto, bypassPermissions, manual, dontAsk, plan)`, `--restricted` ("removes the built-in tools that run commands or code ... ignores user, project and local settings"), `--safe-mode`, `--bare`, `--max-budget-usd` (print mode only), `--session-id <uuid>`, `-w/--worktree [name]`, `--fork-session`. Docs: `claude --bg --exec '<cmd>'` runs a shell job with no model (output only in memory, cleaned ~5 min after exit); `--bg` + `-p` rejected.
- Use: effort panel can set `--effort` at dispatch; `--session-id <uuid>` lets Bullshark pre-assign the transcript file name (known before launch); `--restricted`/`--safe-mode` presets for scheduled/unattended runs; `--exec` for cheap scheduled commands. Caveat: `--max-budget-usd` does not apply to `--bg`; run limits must stay Bullshark-side (or goal turn clause, item 9).

## 9. `/goal` completion condition (and `/loop`)  [docs]
- https://code.claude.com/docs/en/goal : `/goal <condition>` keeps Claude working until a model judges met/impossible; `/goal` shows condition, elapsed, turns evaluated, token spend, last reason; `/goal clear`; restored on resume (turn count/timer reset); works with `-p` and Remote Control; transcript records achieved/failed entries; condition up to 4,000 chars; "include a turn or time clause ... such as `or stop after 20 turns`". Goal pauses/clears on errors ("Goal paused", "Goal cleared after an unrecoverable error"); background work defers evaluation, check-ins at 30 min (v2.1.234+; idle check-ins v2.1.236, capped v2.1.246); `CLAUDE_CODE_GOAL_CHECKIN_MINUTES`. Needs hooks enabled (not under `disableAllHooks`/`--bare`).
- Agent view: `/loop` sessions show `✢` sleeping with run count/countdown.
- Use: first prompt of a scheduled/run-limited session can be `/goal ... or stop after N turns` giving a native run limit; Bullshark can parse goal verdict entries from the transcript for a "goal met/failed/paused" chip on the timeline. Caveat: exact JSONL shape of goal entries not documented in what I read - inspect a real transcript before parsing.

## 10. Agent-view summaries / recap / peek text  [docs]
- Row summaries: working rows show what the session says it is doing (updated at most every 15 s without a model request, rewrite every few minutes), blocked rows show the question; recap posted on attach; `/recap` command. 2.1.326: "Fixed the automatic session recap being sent after a reply billed to usage credits". Peek shows pending question, result of a finished session, linked PRs, "waiting 3m". `CLAUDE_CODE_DISABLE_AGENT_PROGRESS_SUMMARIES=1` disables subagent progress summaries (changelog 2.1.323, available since 2.1.318).
- Use: no documented CLI/JSON field exposes the summary or peek text, so Bullshark should keep deriving it from `claude logs <id>` tail or last transcript assistant message; do not rely on summaries existing. [docs only; absence from `--json` verified locally].

## 11. OpenTelemetry metrics/events as a cost source  [docs]
- https://code.claude.com/docs/en/monitoring-usage : metrics `claude_code.cost.usage` (USD), `token.usage` (input/output/cacheRead/cacheCreation), `session.count`, `active_time.total`, `commit.count`, `pull_request.count`, `lines_of_code.count`; events `api_request` (tokens, cost, duration), `api_error`, `tool_decision`, `tool_result`, `user_prompt` (2.1.325: `delivery.mode: "mid_turn"` and `prompt.id`), `subagent_completed`. Exporters: otlp, prometheus (scrape localhost:9464/metrics), console; `OTEL_LOG_RAW_API_BODIES=file:/dir`; traces beta (`CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1`). OTEL env vars are ignored in project settings; must be shell or user settings. 2.1.326: `OTEL_RESOURCE_INCLUDE_HOST`.
- Use: optional exact live cost/cache facts per prompt (OTLP receiver in Bullshark via env passed when launching), cross-checking transcript-derived numbers. Caveat: env must be set where the supervisor starts the session (daemon inherits the dispatching shell's PATH/provider env per docs; unclear for arbitrary OTEL vars - verify). Cost in transcripts remains the offline source.

## 12. Trust, auth and gateway behaviours that change dispatch outcomes  [docs, changelog 2.1.323-2.1.326]
- 2.1.326: "`--add-dir` ... `claude --bg` refuses such a folder" (untrusted); `claude --bare --bg` errors if the background service lacks the API key; background sessions lose gateway export "after a crash ... they now stop before any model request". 2.1.325: background sessions on claude.ai login no longer use/bill an API key from the starting shell. 2.1.323: `/logout` in a background session "signs out every session on the computer"; `--trust-workspace false` runners cannot have hooks disabled by repo settings. Agent view: `blocked` also covers "an expired login, or a first prompt started without text". Local `-p` help: workspace trust dialog skipped in non-interactive mode. 2.1.325/2.1.326: scheduled tasks and `/loop` now ask before running a skill that declares `allowed-tools` or hooks (add `Skill(name)` to `permissions.allow`); "Always allow" changes can leave scheduled tasks waiting.
- Use: after a `--bg` dispatch, poll briefly and map a refusal/immediate `blocked` to an actionable message (trust the folder interactively first; log in again); warn that scheduled runs may stall on skill/permission prompts and show them as `blocked` with `waitingFor`; never offer /logout from a tab without a warning.

## Other things noticed (not full items)
- Unattached finished sessions' processes stop after ~1 h; sessions "survive sleep" (supervisor reconnects) - docs agent-view.
- `--resume` on a running session: "starts a copy and says so" (local help); changelog 2.1.323 `CLAUDE_CODE_RESUME_HINT_COMMAND` lets a launcher set its own resume hint in the exit text.
- `claude purge [path]` deletes a project's transcripts/tasks/file history (local help) - dangerous to archive/history features; Bullshark archive should snapshot before. `cleanupPeriodDays` cleanup (2.1.323) deletes old transcripts - a reason to archive.
- Transcript robustness fixes (2.1.325/326): resumed sessions previously lost recent turns after crashes; JSONL may lag the in-memory conversation (hooks page) - tolerate partial last line.
- `--include-hook-events`, `--output-format stream-json` with `--input-format stream-json` and `--replay-user-messages` (local help) are the only structured two-way channel, but only for `-p`, not `--bg`.
- Not found: no documented `agents --json` field for goal, cost, tokens, branch, worktree path or PR; no `claude send`; no usage/cost API subcommand locally (`/usage`, `/cost` are slash commands only).
